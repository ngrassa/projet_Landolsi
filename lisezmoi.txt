1. PRINCIPE
-----------
- Le dépôt GitHub est PUBLIC. La sauvegarde de la base (e-mails, téléphones,
  adresses, hachés de mots de passe) n'y est donc JAMAIS versionnée, même
  chiffrée : une fois publiée, elle ne pourrait plus être retirée.
- Seules les sommes SHA-256 de référence sont dans le dépôt (db/backup/) :
    landolsi_tires.dump.gpg.sha256   somme de l'archive chiffrée
                                     (= version attendue par le pipeline)
    landolsi_tires.dump.sha256.txt   somme de l'archive déchiffrée
- Le pipeline télécharge l'archive depuis un stockage PRIVÉ, vérifie sa
  somme, la déchiffre et la restaure.

3. FICHIERS DU DÉPÔT
--------------------
- scripts/restore-encrypted-backup.sh
    Vérifie la somme de l'archive, la déchiffre, puis restaure avec
    restore-db.sh. Refuse une archive différente de la version de référence.
      DB_BACKUP_PASSPHRASE='...' scripts/restore-encrypted-backup.sh -- \
          --target-db landolsi_verif --create --env-file backend/.env
      scripts/restore-encrypted-backup.sh --archive /chemin/landolsi_tires.dump.gpg \
          --passphrase-file ~/.config/landolsi/db-backup.passphrase \
          --decrypt-only /tmp/landolsi_tires.dump

- .github/workflows/db-restore.yml
    * verify      : automatique à chaque modification de db/backup/ ou des
                    scripts ; télécharge l'archive, la restaure dans un
                    PostgreSQL 16 éphémère et vérifie les comptages.
                    Aucun effet sur le serveur.
    * restore-ec2 : manuel uniquement (Actions > Restauration base de données
                    > Run workflow, target = ec2, confirm = RESTAURER).
                    Sauvegarde d'abord la base du serveur, arrête l'API,
                    restaure, redémarre, contrôle /health.

- Documentation : README.md §20 et docs/deployment/database-backup-restore.md §6.

5. ACTIONS À FAIRE PAR L'ADMINISTRATEUR
---------------------------------------
a) Déposer l'archive dans un dépôt GitHub PRIVÉ :

     gh repo create ngrassa/landolsi-backups --private --clone
     cd landolsi-backups
     cp ~/.local/share/landolsi/backups/landolsi_tires.dump.gpg .
     git add . && git commit -m "Sauvegarde 2026-10-30" && git push -u origin HEAD
     cd ..

b) Créer un jeton GitHub "fine-grained" en lecture seule (Contents: Read)
   limité au dépôt landolsi-backups (Settings > Developer settings >
   Personal access tokens > Fine-grained tokens).

c) Déposer les secrets dans le dépôt projet_Landolsi :

     gh secret set DB_BACKUP_PASSPHRASE --repo ngrassa/projet_Landolsi \
         < ~/.config/landolsi/db-backup.passphrase
     gh secret set DB_BACKUP_URL --repo ngrassa/projet_Landolsi \
         --body "https://raw.githubusercontent.com/ngrassa/landolsi-backups/main/landolsi_tires.dump.gpg"
     gh secret set DB_BACKUP_TOKEN --repo ngrassa/projet_Landolsi
         (coller le jeton de l'étape b quand il est demandé)

   Adapter "main" si la branche du dépôt privé porte un autre nom.
   Alternative S3 : URL présignée dans DB_BACKUP_URL, sans DB_BACKUP_TOKEN.

d) Pousser une modification (déclenche le job verify) - déjà fait le 30/10 :

     git add .gitignore README.md lisezmoi.txt docs/deployment/database-backup-restore.md \
         .github db/backup scripts/restore-encrypted-backup.sh
     git commit -m "Sauvegarde chiffrée hors dépôt et restauration CI/CD"
     git push origin master

   Résultat visible dans l'onglet Actions ; relancer à la main :
     gh workflow run db-restore.yml --repo ngrassa/projet_Landolsi

e) Pour utiliser plus tard le job restore-ec2 :
   - secrets supplémentaires : EC2_HOST, EC2_SSH_KEY, EC2_KNOWN_HOSTS
       (EC2_KNOWN_HOSTS : ssh-keyscan -t ed25519 18.213.152.8)
   - le Security Group limite SSH à l'IP de l'administrateur : l'ouvrir
     temporairement aux runners GitHub Actions, ou utiliser un runner
     auto-hébergé.
   - conseillé : ajouter des relecteurs obligatoires à l'environnement
     GitHub "production".
